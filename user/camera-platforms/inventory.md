Вид места:

- **(a)** число, измеренное или подобранное на одном устройстве;
- **(b)** безусловное поведение, выбранное из-за особенности одного устройства;
- **(c)** уже адаптивно: читает Camera2 или определяет на ходу;
- **(d)** учится на телефоне и хранится по объективам.

Решения:

- **У** — универсально: остаётся в общем коде. Механизм нужен всем, проверяется по Camera2, либо число — общая эвристика, предел, охватывающий разные устройства, или выбор владельца по вкусу.
- **П=** — уходит в профиль, **нейтральное значение = прежнее**. Число измерено или подобрано на одном устройстве (README: такие числа не живут в общем коде), но лучшей оценки для неизвестного телефона нет. Комментарий о происхождении переезжает вместе с числом. Слой может его переопределить.
- **Т** — Tensor: в слое Tensor прежнее, у нейтрального профиля другое (указано). Нейтральное значение берётся только из пути, который уже работает в коде.
- **Флаг** — в профиле появляется переключатель поведения; нейтральное = сегодняшнее поведение, другое значение ставит слой конкретной платформы.
- **Проба** — выясняется на телефоне на ходу, профиль не нужен.
- **Испр.** — универсальный механизм с ошибкой: чинится в общем коде в указанной сессии. Pixel при этом не должен меняться; это подтверждается на вехе, а не утверждается здесь.
- **Не трогаем** — с причиной.

Вердикт 01 (OnePlus 11): **держится** / **не держится** / **н/п** — не применимо / **н/пр** — не удалось проверить.

## A. Кто кого создаёт (точки подвода профиля)

- Внедрения зависимостей нет: только `object` и ручное создание.
- `CameraActivity` получает `CameraViewModel` через `viewModels()`.
- `CameraViewModel` создаёт `CameraController(application)` (VM:97). Контроллер получает только `Context`; настройки приходят аргументами вызовов.
- Настройки: `CameraSettingsStore.load` (VM:105), неизменяемый `CameraSettings`.
- `ViewfinderRenderer` создаётся в `ui/Viewfinder.kt`:45–51. Данные о телефоне доходят до него только через `Frame` (гамма, усиление, поворот, зеркало, цвет). Матрица YUV и запасной путь EGL — внутри рендерера.
- `VideoRecorder.create(...)` — фабрика, вызывается из VM:~324; она же строит `VideoSink`.
- `ShotSaver` — глобальный `object` (SS:124). Данные снимка приходят в `Shot` (SS:73–104). Константа `EXTRA_BLACK` читается из `CameraController` напрямую (CC:938).

## B. Ключи запросов Camera2

`setCommon` (CC:1599–1646) действует на все запросы.

- **Без проверки:** `CONTROL_MODE`, `CONTROL_AF_MODE`, `CONTROL_AE_MODE`, `FLASH_MODE`, `CONTROL_AWB_MODE`, `CONTROL_VIDEO_STABILIZATION_MODE = OFF`, `CONTROL_AE_LOCK`, `CONTROL_AE_EXPOSURE_COMPENSATION` (значение из характеристик).
- **С проверкой наличия:** диапазон fps, области AE/AF (`setRegions`, CC:1760–1770), OIS, три варианта тон-режима (через `setForLens`, то есть и на физический объектив).
- **Вне `setCommon`:** распознавание лиц — в `repeatPreview` (CC:572, с проверкой); карта виньетирования — в снимке, серии и длинной выдержке (CC:846, 975, 1156, с проверкой); `AWB_LOCK` — только длинная выдержка (CC:1125).
- **Диапазон fps:** снимок без вспышки (и raw meter), серия, длинная выдержка ставят `stillFpsRange`; снимок со вспышкой остаётся на `previewFpsRange`.
- **Снимок со вспышкой, без проверки:** `CONTROL_ENABLE_ZSL = false`, ручные выдержка, ISO и длительность кадра, boost 100, `FLASH_MODE_SINGLE`. ZSL выключают также серия и длинная выдержка.
- **Отдельного запроса для видео нет:** видоискатель в видеорежиме использует запрос превью.
- **Не задаются вовсе:** `CONTROL_CAPTURE_INTENT`, `NOISE_REDUCTION_MODE`, `EDGE_MODE`, `COLOR_CORRECTION_*`: превью остаётся с настройками шаблона.

## E. Условия по версии Android и расширениям

- **API 31+:** режим максимального разрешения (CC:~500, ~1653, ~1872; MR:77, 211, 894, 898).
- **API 33+:** `SurfaceTexture.dataSpace`, иначе 0 (VF:460).
- **API 34+:** высота над уровнем моря (VM:~1347), тип foreground-сервиса (SS:~646).
- **GL:** `GL_EXT_YUV_target` выбирает путь YUV или RGB (VF:192).
- **EGL:** `EGL_RECORDABLE_ANDROID` с запасным путём (VO:89).
