# Сессия 03: API и архитектура

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 03 плана `user/camera-platforms/`: утверди с автором ветки архитектуру слоя платформ и создай каркас пакета `app.rawboy.camera.platform` — типы профиля, слияние слоёв, слой Tensor с прежними числами и тесты. Общий код камеры профиль пока не читает. Сначала прочитай `CLAUDE.md`, `user/camera-platforms/README.md` (раздел «Архитектура»), `inventory.md`, `results/01.md`, `results/02.md`, этот файл.

## Зачем

API — шов между общим кодом и всеми будущими платформами. Если его форма поплывёт после выноса, переделывать придётся и общий код, и каждый слой.

## Что сделать

1. **Архитектура — автору ветки.** Короткое описание простым языком: кто чем владеет, какие границы, какие инварианты (README, раздел «Архитектура», с поправками по 01 и 02). Решения записать в `decisions.md`.
2. **Типы профиля** (решение 9):
   - неизменяемая структура данных, разбитая по областям: превью, снимок, шум, вспышка, видео;
   - интерфейсы-стратегии только там, где таблица 02 показала разный алгоритм; у каждого — реализация по умолчанию;
   - у каждого поля KDoc: что это, единицы, откуда число.
3. **Слои и слияние** (решения 4, 14): слой задаёт только то, что переопределяет; порядок нейтральный → чип → производитель → модель; результат — полный профиль без пустых полей.
4. **Описание телефона** — тип, который вернёт детектор в сессии 07 (чип, производитель, модель). Сам детектор здесь не пишется.
5. **Слой Tensor** со значениями по таблице 02, равными прежним константам.
6. **Точки подвода** (см. `inventory.md`, раздел A) — решить и записать:
   - как профиль попадает в `CameraController`, в `ShotSaver` (через `Shot` или иначе), в `VideoRecorder`;
   - какие параметры получит движок (`ViewfinderRenderer`, `EncoderSurface`), чтобы не импортировать `platform/` (решение 10);
   - где создаётся профиль и кто его держит.
7. **Временное правило до сессии 07:** активный профиль для всех телефонов — Tensor.
8. **Слой модели:** отдельная папка или таблица внутри слоя производителя — решить с автором ветки.

## Тесты

- Слияние: переопределено только заданное, порядок слоёв соблюдён, пустой слой ничего не меняет.
- Tensor: каждое значение равно прежней константе. Пока константы живы — сравнение с ними; после выноса в 04–06 в тесте остаётся литерал.

## Не делать

- Не менять `CameraController`, `ShotSaver`, `CameraViewModel`, движок: общий код начинает читать профиль в сессиях 04–06.
- Не писать слои Qualcomm и OnePlus.
