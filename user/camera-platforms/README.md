## Зачем

RawBoy Camera написана и настроена на одном телефоне, Pixel 9 Pro. Проверок «если это Pixel» в коде нет: особенности Pixel зашиты как константы и как допущения, которые действуют на всех телефонах. На других телефонах это даёт сбои и расхождения:

- на OnePlus 11 (Snapdragon 8 Gen 2) запись видео не работает совсем: таймер идёт, файл не появляется;
- для Samsung уже пришлось добавить точечную ветку по производителю прямо в настройках;
- поддержка каждого нового телефона сейчас означает правку констант в нескольких больших файлах.

## Главная идея

Общий код камеры не знает о конкретных телефонах. Всё, что зависит от чипа, производителя или модели, лежит в **профиле платформы**. Приложение при запуске само определяет телефон и собирает профиль из слоёв.

```
нейтральный профиль  →  слой чипа  →  слой производителя  →  слой модели
     generic/           tensor/         oem/samsung/          (внутри слоя
                        qualcomm/       oem/oneplus/           чипа или oem)
```

- Каждый следующий слой переопределяет только то, что в нём задано.
- Телефон без своего слоя получает нейтральный профиль.
- Pixel 9 Pro после выноса ведёт себя в точности как сейчас.

Отдельно от профилей — **проба на устройстве**: то, что можно надёжно выяснить на самом телефоне (рабочий вариант поверхности видеокодера), приложение проверяет само и запоминает результат.

## Действующие решения — сводка

Полные формулировки — в [decisions.md](decisions.md).

**Организация**
- Владелец репозитория согласовал работу. На вехах он получает APK из ветки и проверяет Pixel 9 Pro; слияние согласуется в конце (1, 2).
- Работа идёт в ветке `camera-device-compat`, коммиты пушатся в неё напрямую (1).
- План лежит в `user/camera-platforms/`, коммитится в ветку и удаляется перед слиянием (15).
- Только Android. iOS, веб и порты движка на TS и Swift не трогаем (10).

**Профили и автодетект**
- Автодетект платформы в приложении обязателен (3).
- Профиль собирается слоями: чип → производитель → модель (4).
- Неизвестный телефон получает нейтральный профиль без обходов, а не числа Pixel (5).
- Что универсально, что уходит в Tensor и каково нейтральное значение — решает таблица по каждому месту, которую утверждает автор ветки до написания кода (6).
- Находки на OnePlus раскладываются по природе: драйвер GPU и кодер — слой Qualcomm; поведение камеры и обработка превью — слой OnePlus; числа сенсоров — слой модели (14).
- Слой вендора чипа должен давать как минимум адекватное поведение на большинстве телефонов с этим чипом: слой Qualcomm не остаётся пустым, а его значения безопасны для других Snapdragon (20).
- Таблица решений по каждому месту — в [inventory.md](inventory.md) (28). Число, измеренное на одном устройстве, уходит в профиль, даже если нейтральное значение равно прежнему (33).
- Значения Tensor — в слое чипа; старые Pixel на Snapdragon получают слой Qualcomm (29, 32).
- `oem/samsung` закрепляет сегодняшнее поведение Samsung, пока его не проверят (30).
- Нейтральный видоискатель считает превью sRGB; `EXTRA_BLACK` у нейтрального профиля 0 (31, 34).
- Один слой — один файл с условием применения; модель — файл в папке производителя или чипа; общие куски — «черты» в `platform/traits/`; порядок — по уровню слоя (38).
- Числа П= повторены в слое Tensor, чтобы правка нейтрального профиля не сдвигала Pixel (37).
- API расширяется только добавлением полей с сегодняшним поведением по умолчанию; места заранее не резервируются (39). Области «видео» пока нет (40).
- До сессии 07 чип у всех телефонов считается Tensor, слои производителя действуют по `Build.MANUFACTURER` (42).

**Код**
- Профили — пакет `app-camera/src/main/java/app/rawboy/camera/platform/` (8).
- API профиля: неизменяемые данные плюс несколько интерфейсов-стратегий там, где отличается алгоритм (9).
- Движок `:engine` о платформах не знает и получает значения параметрами. Списки производителей в `AutoTone.kt` и `noise.cpp` остаются как есть (10).
- Сбой записи видео чинится пробой на устройстве; поведение Pixel при этом не меняется (7).
- Debug-сборка получает отдельное имя пакета только через необязательный параметр Gradle, по умолчанию он выключен (16).

**Диагностика** (17)
- строка в logcat при запуске;
- строка профиля в Настройках;
- отчёт об устройстве кнопкой в Настройках;
- ручной выбор профиля в debug-сборке.

**Приёмка на OnePlus 11** (11, 12)
- главное: запись видео, видоискатель = снимок, качество снимка, вспышка;
- дополнительно: все объективы и селфи, склейка 8 кадров, максимальное разрешение, длинная выдержка, трекинг, QR, HDR-карта.

## Архитектура (утверждена в сессии 03, решения 37–42)

```
app-camera/src/main/java/app/rawboy/camera/
  platform/
    CameraPlatform.kt      профиль по областям (preview, still, noise, flash), проверка диапазонов
    PreviewColor.kt        стратегия цвета превью и её вход из простых чисел
    PlatformLayer.kt       правка профиля, уровень слоя, слой = условие + правка
    PhoneDescription.kt    описание телефона (вендор чипа + строки Build)
    PlatformRegistry.kt    список слоёв и их слияние
    ActivePlatform.kt      профиль процесса (до 07 чип у всех — Tensor)
    PlatformDetector.kt    автодетект (сессия 07)
    generic/               нейтральный профиль
    tensor/                Google Tensor (сегодняшние числа)
    qualcomm/              Snapdragon
    oem/                   samsung/, oneplus/ (модели — файлами рядом: oneplus/Cph2447.kt)
    traits/                общие куски нескольких слоёв
```

- Слой задаёт только то, что переопределяет. Порядок задаёт уровень: вендор чипа → SoC → производитель → модель.
- Добавить чип или модель = файл + строка в `PlatformRegistry.layers` + тест-закрепление.
- Точки подвода — решение 42 и [results/03.md](results/03.md).

Кто чем владеет:

| Часть | Владеет | Не делает |
|---|---|---|
| `PlatformDetector` | читает `Build.*`, возвращает описание телефона | не выбирает значения |
| `PlatformRegistry` | по описанию собирает профиль из слоёв | не читает `Build.*` |
| Слои (`tensor/`, `qualcomm/`, `oem/`) | значения и стратегии одной платформы | не обращаются к `CameraController`, `ShotSaver`, UI |
| Общий код камеры | логика съёмки, читает готовый профиль | не содержит имён телефонов и чисел, измеренных на одном телефоне |
| `:engine` | принимает значения параметрами | не зависит от `platform/` |

Куда профиль подводится (решение 42):

- `ActivePlatform.profile` читает только `CameraViewModel` и раздаёт явно;
- `CameraController` — параметр конструктора (04);
- `ShotSaver` — поле `Shot.platform` (05); `CameraSettings.develop()` — пороги шума параметром (05);
- движок — ничего из профиля: цвет превью уже идёт через `Frame.color`, EGL-параметры видео заполняет проба (06, 09);
- `VideoRecorder` профиля не получает.

## Вехи с проверкой на Pixel

На каждой вехе ветка запушена, автор ветки отправляет владельцу репозитория APK и чек-лист из отчёта сессии.

Следующая сессия начинается после его ответа (решение 23).

Как владелец ставит сборку (решение 24; автор ветки согласует с ним до M1):

- владелец сам собирает ветку своим ключом и ставит поверх своей версии: выученная калибровка (`previewScales3`, `flashGuides`) сохраняется;
- APK от автора ветки — запасной путь: он подписан другим ключом и поверх установленной версии не встанет;
- при пустой калибровке первые снимки на каждом объективе расходятся с видоискателем независимо от наших правок, поэтому сравнивать нужно после 2–3 снимков на объектив.

| Веха | После сессии | Что проверяет владелец репозитория на Pixel 9 Pro |
|---|---|---|
| M1 | 06 | Ничего не изменилось: фото, видоискатель, вспышка, видео, серия |
| M2 | 07 | Телефон определился как Tensor и получил свой профиль |
| M3 | 09 | Видео пишется как раньше |
| M4 | 15 | Полная приёмка по чек-листу, релизная сборка с R8 |

## Общие правила сессий

Работай в корне репозитория. Сначала `CLAUDE.md`: он описывает устройство кода, сборку и уже найденные ловушки. Перед работой:

- План читается так: этот README, файл своей сессии, решения по номерам из него в [decisions.md](decisions.md), отчёты сессий, от которых зависит своя.
- Широкий поиск по репозиторию — read-only субагентом (модель Sonnet). Основной агент читает точные места.
- Для Camera2, MediaCodec, EGL и Gradle источник истины — документация Android (Context7) и живой телефон, а не память модели.

Главный инвариант:

- **Поведение Pixel 9 Pro не меняется.** Каждое вынесенное значение в профиле Tensor равно прежней константе, и это закреплено тестом.
- До сессии 07 активным профилем для всех телефонов жёстко назначен Tensor, поэтому сессии 04–06 не меняют поведение ни на одном телефоне.

Язык (решение 26, строгое правило):

- **сообщения коммитов и комментарии — только на английском**: комментарии в коде, KDoc, комментарии на GitHub;
- файлы плана в `user/` и общение с автором ветки — на русском.

Код:

- стиль окружающего кода, KDoc у публичных типов, короткие комментарии «почему»;
- новых зависимостей не добавляем;
- общий код камеры после выноса не содержит имён телефонов и чисел, измеренных на одном телефоне; комментарий о происхождении числа переезжает вместе с числом в слой;
- движок получает значения параметрами и не импортирует ничего из `platform/`;
- GPL-код не копируется и не портируется, LibRaw не патчится (`CLAUDE.md`, раздел Conventions).

Тесты и сборка:

- `./gradlew :app-camera:testDebugUnitTest :engine:testDebugUnitTest`, затем `./gradlew :app-camera:assembleDebug`;
- сборка за 1–4 секунды могла ничего не пересобрать: при сомнении `--rerun-tasks`;
- тест проверяет результат, а не факт вызова;
- для слоёв — тест слияния (переопределено только заданное) и тест «Tensor равен прежним константам».

Телефон (OnePlus 11 по adb):

- версию из Google Play не трогаем: наша debug-сборка стоит рядом под другим именем пакета (решение 16);
- буфер logcat на телефоне хранит около 5 минут: лог пишется потоком в файл в scratchpad до начала опыта;
- `input tap` Compose иногда игнорирует: нажатия делаются как `input swipe x y x y 80`;
- результат измеряется (пары «видоискатель / снимок», средние и разброс каналов через PIL), а не оценивается на глаз;
- тестовые снимки и видео после сессии удаляются с телефона, если автор ветки не просил оставить.

Документация:

- видимое пользователю изменение (строка профиля, отчёт, работающее видео) — правка `docs/camera.md`, запись вверху `CHANGELOG.md`, справка `ui/Help.kt`;
- чистый рефакторинг в `CHANGELOG.md` не попадает;
- `CLAUDE.md` дополняется разделом о слое платформ в сессии 15.

Отчёты `results/NN.md`: статус, SHA, решения, что сделано, доказательства (тесты, прогоны на телефоне), известные ограничения. Для сессии с вехой — чек-лист для владельца репозитория.

Конец сессии в плане:

- новые решения дописываются в конец [decisions.md](decisions.md) со следующим номером; если они меняют действующее правило — ещё и в сводку выше;

- в README обновляются только «Состояние» и строка сессии в «Порядке»;
- в `user/` только Markdown;
- никаких личных путей, серийных номеров, имён аккаунтов и сырых логов: сырые данные остаются в scratchpad.

Git:

- ветка `camera-device-compat`, `main` не трогаем;
- коммит в конце сессии после зелёных проверок, затем push в ветку;
- каталог `.serena/` в коммиты не входит;
- перед слиянием `user/` удаляется из ветки (решение 15).

## Известные технические факты

**Сбой записи видео на OnePlus 11** (воспроизведён 15 ноября 2026 на версии 1.16.8 из Google Play; CPH2447, SM8550, Android 16):

1. `EncoderSurface.create()` (`engine/.../gl/VideoOutput.kt`) пробует конфиг `EGL_RECORDABLE_ANDROID` RGBA8888; `eglMakeCurrent` возвращает `EGL_BAD_MATCH`. *В логе есть сама ошибка и переподключение поверхности; что отказал именно recordable-конфиг — вывод из кода.*
2. Запасной путь берёт конфиг контекста видоискателя. `GLSurfaceView` в `ui/Viewfinder.kt` создаётся без выбора конфига, то есть RGB888 без альфы; буферы получаются RGBX_8888. *В логе есть `pixel format: 0x2`, слой видоискателя в SurfaceFlinger — `RGBX_8888_UBWC`; связь с конфигом по умолчанию — вывод из кода.*
3. `c2.qti.hevc.encoder` такой формат не принимает: `unsupported color format`, `Codec consumed 0 of 1 inputs queued`, ошибка MediaCodec 14.
4. Поток кодера завершается (`RawBoyVideo: video encoder stopped`), но `sink.failed` выставляется только при отказе EGL-поверхности, поэтому таймер продолжает идти.
5. На остановке кадров ноль, файл удаляется; пользователь видит «Nothing was recorded».

- Приложение при этом не падает.
- Откат на H.264 не срабатывает: он рассчитан только на отказ HEVC при конфигурации.
- Не проверено: что этот кодер принял бы буферы RGBA.
- `VideoOutput.kt`, `VideoRecorder.kt`, `ViewfinderRenderer.kt` и `ui/Viewfinder.kt` между v1.16.8 и `1574553` не менялись.

**Перечень платформозависимых мест** — [inventory.md](inventory.md). Главное:

- проверок модели телефона в коде камеры нет; единственная ветка по производителю — Samsung (`CameraSettings.withPhoneIspLook`, по полю Make из DNG);
- часть специфики лежит в `:engine`: матрица YUV в `ViewfinderRenderer.yuvToRgb`, поверхность кодера в `VideoOutput.kt`;
- калибровка по объективам (`previewScales3`, `flashGuides`) учится на телефоне сама; ключи содержат только метку объектива;
- тестов на `CameraController`, `ShotSaver`, `ViewfinderRenderer` и `VideoRecorder` нет.

**Автодетект:**

- `Build.SOC_MANUFACTURER` и `Build.SOC_MODEL` есть только с API 31, а minSdk приложения 29: для API 29–30 нужен запасной признак (`Build.HARDWARE`, `Build.BOARD`).
- Точные строки для Tensor и Snapdragon не сняты (телефон отключился от adb до проверки): снять в сессии 01.

**Машина автора ветки** (на 15 ноября 2026):

- нет `third_party/dng_sdk`: без него не собирается ни одна Android-сборка (`checkDngSdk`), команда загрузки — в `third_party/README.md`;
- установлен NDK 30, проекту нужен 27.2.12479018; CMake 3.22.1 не установлен;
- JDK 21 есть (демон Gradle закреплён за ним);
- `keystore.properties` нет: релизная сборка получится неподписанной.

## Контекст, который нельзя потерять

- **Нейтральный профиль меняет поведение на всех телефонах без своего слоя** в момент включения автодетекта (сессия 07): сейчас они работают с числами Pixel. Владелец репозитория должен узнать об этом на вехе M2.
- **Samsung.** Galaxy S25 — Snapdragon, Galaxy Tab S11 Ultra — MediaTek. После автодетекта первый получит слои Qualcomm + Samsung, второй — нейтральный + Samsung. Оба владелец репозитория уже подстраивал вручную; регрессию на них проверить некому.
- **Старые Pixel на Snapdragon** (до Pixel 6) после автодетекта перестанут получать числа Pixel 9 Pro. Что с ними делать — вопрос к таблице решений (сессия 02).
- **`docs/video.md` устарел:** это исходный план видео, в нём сказано, что код не запускался на устройстве.
- **`CLAUDE.md` не описывает видеорежим**, хотя код есть.
- **Числа Samsung** (`SAMSUNG_CONTRAST`, `SAMSUNG_SATURATION`) — первая оценка владельца репозитория по одной паре снимков.
- **Три копии числа 0.06:** `AutoTone.PHONE_KEY`, `CameraController.LONG_EXPOSURE_KEY`, серый в `LumaProgram` видоискателя.
- **Ручной выбор профиля в debug** не должен портить выученную калибровку: под чужим профилем она пишется в отдельное место.
