**Статус:** выполнена. Архитектура утверждена автором ветки, каркас пакета `app.rawboy.camera.platform` написан и покрыт тестами. Общий код камеры профиль пока не читает.

**Дата:** 15 ноября 2026.

Решения 37–42 — в [decisions.md](../decisions.md).

## Утверждённая архитектура

- **Профиль** `CameraPlatform` — неизменяемые данные по областям `preview`, `still`, `noise`, `flash`. Пустых полей нет: каждое значение задаёт нейтральный профиль, слои только заменяют.
- **Слой** = условие «когда применяюсь» + правка профиля. Правка пишется через `copy`, поэтому поле, добавленное позже, проходит через старые слои нетронутым.
- **Раскладка:**
  - один слой — один файл;
  - модель — файл в папке своего производителя или чипа;
  - общие куски — «черты» в `platform/traits/`;
  - порядок задаёт уровень слоя, а не место в списке (решение 38).
- **Расширение API** — только добавлением полей, их нейтральное значение — сегодняшнее поведение. Заранее места не резервируются (решение 39).
- **Границы:**
  - движок о `platform/` не знает;
  - слои не обращаются к `CameraController`, `ShotSaver` и UI;
  - стратегии получают простые числа, а не объекты Camera2;
  - описание телефона читает только детектор (07), реестр `Build` не читает.

```
app-camera/src/main/java/app/rawboy/camera/platform/
  CameraPlatform.kt      профиль и его области; problems() — проверка диапазонов
  PreviewColor.kt        стратегия цвета превью, вход PreviewColorInput, SrgbPreviewColor (по умолчанию)
  PlatformLayer.kt       PlatformPatch (правка, цепочка через +), LayerLevel, PlatformLayer
  PhoneDescription.kt    описание телефона (ChipVendor + строки Build как есть)
  PlatformRegistry.kt    список слоёв, resolve(phone), stack(layers)
  ActivePlatform.kt      профиль процесса; до 07 чип у всех — Tensor
  generic/Neutral.kt     neutralPlatform
  tensor/Tensor.kt       tensorLayer
  traits/Pixel9ProIsp.kt        ispBlackAsPixel9Pro, previewColorFromResult
  traits/UndoIspPreviewColor.kt снятие матрицы ISP (копия CameraController.previewToRec2020)
```

Детектора (`PlatformDetector`) нет, он пишется в сессии 07.

## Типы и поля

| Область | Поле | Нейтральное | Tensor | Строка перечня |
|---|---|---|---|---|
| `preview` | `color` (стратегия `PreviewColor`) | `SrgbPreviewColor` | `UndoIspPreviewColor` | Т: `previewToRec2020` |
| `still` | `extraBlack` | 0 | 1.46e-3 | Т: `EXTRA_BLACK` |
| `still` | `maxStillExposureNs` | 66 666 667 | 66 666 667 | П=: `MAX_STILL_EXPOSURE_NS` |
| `still` | `lookContrast`, `lookSaturation` | 0, 0 | 0, 0 | `oem/samsung` (+25, сессия 05) |
| `noise` | `backIsoScale`, `frontIsoScale` | 4, 8 | 4, 8 | П=: множители шума |
| `noise` | `lutLumaFloor`, `lutColorFloor`, `experimentalLumaFloor`, `experimentalColorFloor` | 12, 70, 22, 70 | 12, 70, 22, 70 | П=: пороги LUT |
| `flash` | `defaultGuide`, `referenceFNumber`, `defaultGainNoDistance` | 16, 1.7, 4 | 16, 1.7, 4 | П=: стартовые числа вспышки |

- Уровни слоёв (`LayerLevel`): `CHIP_VENDOR`, `SOC`, `MANUFACTURER`, `MODEL`. Уровень `SOC` добавлен, чтобы слой одной SoC (например, SM8550) ложился между вендором и производителем.
- Вендоры чипа в описании (`ChipVendor`): `TENSOR`, `QUALCOMM`, `MEDIATEK`, `EXYNOS`, `UNKNOWN`.
- В профиле нет:
  - флага «самостоятельная камера» — появится в 10, решение 39;
  - области «видео» — решение 40.

## Точки подвода (решение 42)

| Кто | Как получает профиль | Сессия |
|---|---|---|
| `ActivePlatform` | собирает один раз на процесс; читает только `CameraViewModel` | 03 (готово, никем не вызывается) |
| `CameraController` | параметр конструктора; raw meter берёт `still.extraBlack` оттуда же | 04 |
| `ShotSaver` | поле `Shot.platform` | 05 |
| `CameraSettings.develop()` | пороги шума параметром (вызовы из живой проявки и из `ShotSaver`) | 05 |
| `ViewfinderRenderer` | ничего нового: цвет уже приходит через `Frame.color`; YUV — «У» | — |
| `EncoderSurface`, `ui/Viewfinder.kt` | параметры «порядок попыток» и «EGL-конфиг», по умолчанию сегодняшние; заполняет проба | 06, 09 |
| `VideoRecorder` | не получает | — |

**Временное правило до 07:** в `ActivePlatform` чип у всех считается Tensor, остальные строки описания берутся из `Build` настоящие. Поэтому слой производителя (`oem/samsung` с сессии 05) срабатывает уже до автодетекта.

## Проверки

- `./gradlew -Prawboy.abis=arm64-v8a :app-camera:testDebugUnitTest :engine:testDebugUnitTest :app-camera:assembleDebug` — зелёные. В камере 58 тестов (было 39, новых 19), в движке 143; падений нет.
- **`PlatformRegistryTest`** (9 тестов):
  - нейтральный профиль годен;
  - телефон без своих слоёв получает нейтральный профиль;
  - слой меняет только заданное;
  - пустой слой меняет только список имён;
  - порядок по уровню, а не по списку, внутри уровня — по списку;
  - производитель переопределяет стратегию чипа;
  - применяются только подходящие слои;
  - каждый зарегистрированный слой даёт годный профиль;
  - `problems()` ловит выход за диапазон.
- **`TensorLayerTest`** (6 тестов):
  - каждое значение сравнивается с прежней константой, а private — с литералом (решение 41);
  - отдельный тест: Tensor восстанавливает свои значения, даже если нейтральный профиль сдвинут (решение 37).
- **`PreviewColorTest`** (4 теста):
  - sRGB-путь;
  - снятие матрицы ISP отказывает при неполных данных и вырожденной матрице;
  - при нейтральном ISP остаётся sRGB→Rec.2020;
  - любой цвет камеры, пропущенный через ISP и обратно, попадает туда же, куда его кладёт декодер raw, с точностью до масштаба белого.

## Известные ограничения и что передаётся дальше

- **Код снятия матрицы ISP временно существует в двух копиях:** `CameraController.previewToRec2020` (общий код в 03 не трогается) и `UndoIspPreviewColor`. **Сессия 04** переводит контроллер на стратегию и удаляет его копию вместе с `SRGB_TO_REC2020`, если та больше нигде не нужна. Тест 04 сравнивает обе копии на входах с телефона.
- **Строки детектора для Tensor не сняты** (Pixel только у владельца репозитория). В коде их нет, кроме `ChipVendor.TENSOR`; распознавать его научит сессия 07.
- **Сессии 06 по решению 42 не нужен параметр YUV для `ViewfinderRenderer`**: таблица 02 отнесла `yuvToRgb` к «У». Сам файл 06 не правился (README: в плане меняются только «Состояние» и строка сессии), сессия 06 читает этот отчёт.
- **Числа П= у нейтрального профиля — числа Pixel 9 Pro**, как утверждено в 02. Комментарии о происхождении лежат и в `generic/Neutral.kt`, и в `tensor/Tensor.kt`.
- **README:** кроме «Состояния» и строки сессии обновлены раздел «Архитектура» (он ждал утверждения в 03), сводка решений и таблица открытых вопросов (закрыт вопрос о слое модели).
